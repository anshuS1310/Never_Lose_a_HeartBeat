# Design note

## Architecture

One collector owns the mock's single TCP connection and alternates sensor reads. For each reply it extracts the literal `data` JSON array, checks its CRC-32 before trusting values, validates 24-bit signed integers, and commits samples plus reported losses and next-index cursor in one SQLite transaction. The primary key `(session,sensor,index)` prevents duplicate disk samples. SQLite WAL with `synchronous=FULL` makes committed replies durable across process crashes and correctly functioning storage power cuts. A mock session ID change starts a new local session; any unknown tail of an unfinished prior session is recorded with `to_index:null` and `reason:"mock_restarted"`.

A separate thread turns committed indexes into one-second frames once both sensors' indexes are resolved and the next ECG sample is known. A bounded rolling ECG buffer reads only the 400 new values per window, scans peaks, and keeps the preceding context and peak anchor for cloud processing; a restart rebuilds it from SQLite. Cloudflare D1 keys frames by `(session,window)`. Identical retries are acknowledged, while a conflicting frame gets HTTP 409. The Worker computes online results and timestamps them with its own clock. When the network fails, the device computes and stores offline results with the same window rules. It also caches each offline frame's serialized payload on disk, so catch-up does not need to rebuild it from millions of sample rows. Offline frames and their saved results upload in atomic batches of up to eight windows. The uploader gives recent online frames a separate pool, so backlog does not delay fresh online work. Collection does not wait for the cloud.

## Processing and switching

Frames cover sample indexes `400w..400w+399` for each sensor. Missing positions remain `null`; statistics use only present samples. ECG peaks require 800 present predecessors, one present successor, a strict neighbor maximum, a value above half the prior-800 maximum, and 100 samples from the previous accepted peak. Heart rate uses accepted peaks in the last five seconds only when all 2,000 ECG samples are present. Decimal values round to one decimal place. Python and Worker JavaScript implementations are compared by a parity test.

Health checks run every two seconds while uploads are absent. One failed health check or upload marks offline, and one successful health check marks online. A health request has a four-second timeout, within the ten-second switching target. All timings use a monotonic device clock. Upload acknowledgments alone advance the local cloud count. The cloud may already hold a frame if its acknowledgment was lost, but retry is safe.

## Guarantees and limits

Every **committed** sample remains on device storage and is exported unchanged and once. Any sample received in a reply but not committed at the instant of a power cut can be lost: at most one reply of at most 400 samples, **one second per sensor**, under the documented mock protocol. This is the stated maximum for received in-flight data, assuming the storage honors flushes. The mock itself runs on the same board; its unread tail can disappear on power loss, and its exact unknown end is recorded as an open-ended loss after restart. There is no defensible finite bound for data the mock never delivered, especially if it had stopped answering before power loss. Cheap SD cards can misreport flush completion.

Free-tier quotas, an unreachable cloud, or a full device disk can interrupt online service. A 16 MB preallocated reserve is released on the first SQLite full-disk error, and the collector retries from its committed cursor. This is bounded emergency capacity, not an indefinite guarantee: if the disk fills again, it cannot truthfully guarantee continued collection or loss logging. The included simulator exercises this repository's TCP contract, but compatibility with other sensor sources has not been established. `VALIDATION.md` records the measured ARM64 tests and their limits.
